## Claims reworded or dropped after the live read

- Non-negotiable 2: the plan's "never add a new `middleware.ts`" was too absolute. The upgrade guide
  and the Next.js 16 post both say the Edge runtime is not supported in Proxy and `middleware.ts`
  remains for Edge use. It now reads "don't add a new one unless you need the Edge runtime".
- Non-negotiable 7: reworded from "type with" to describe the helpers as global and generated,
  which is what the pages state.
- Non-negotiable 12: reworded from "Stream long responses ... as a Web `ReadableStream`" to the
  documented mechanism: pass a `ReadableStream` to `new Response`.
- Non-negotiable 13: reworded to the post's exact claim: caching with Cache Components is opt-in.
- Placement rule 3: the page says routes in different groups "should not" resolve to the same path,
  so the rule says "should not" instead of "must not".
- Not added to the tree: `middleware.ts`, `next-env.d.ts` and `.env*` files (a deprecated file, and
  files the docs say should not be tracked, not layout decisions).
